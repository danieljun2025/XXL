# 启用兑换码：上线清单（#15）

目标：打开 `REQUIRE_CODE`，让「开始新测试」需要兑换码，同时不把任何人拦在门外，出问题 1 分钟内能退回。

## 策略：先用一个长期通用码软启动
| 阶段 | 做法 | 为什么 |
|---|---|---|
| **A 软启动（现在）** | 生成**一个长期通用码**（不限时间，人数设上限，如 100），发给朋友、早期用户和第一批买家 | 简单，不用逐个发码；每人对同一个码限用一次；随时可作废或调上限 |
| **B 有真实订单后** | 作废长期码，改用**一次性码**逐单发放；闲鱼自动发货用卡密导入（#19） | 一单一码，转发无效，能对上订单 |

长期码的风险是会被传播。控制办法：**设人数上限**（后台看"已用 N / 上限"，增长异常就作废换码）；码不要用好猜的词（建议留空让系统自动生成 6 位，或自定义 8 位以上的随机字母数字）；码只放在你的密码管理器里，**不要写进仓库或文档**。

## 前置条件（先确认）
- [ ] v1.3.0 已部署（Render 状态为 Live）
- [ ] `anchor.matchgamers.com/privacy.html` 和 `/terms.html` 能打开（#12 #13）
- [ ] 已在后台下载第一份数据库备份并存好（#14）
- [ ] `npm run smoke -- https://anchor.matchgamers.com` 全部通过

## 步骤（约 15 分钟）
1. **生成长期通用码**：后台 →「兑换码管理 →」→ 选「通用码（多人共用）」
   - 自定义码：留空（自动生成）
   - 有效时长：**留空**（长期有效）
   - 最多使用人数：**100**（以后可再生成新码）
   - 备注：`长期通用码（软启动）`
   - 点「生成」，复制并保存到密码管理器。
2. **启用开关**：Render → 服务 `career-anchor` → Environment → Add Environment Variable：`REQUIRE_CODE` = `1` → Save Changes。服务会自动重启，等状态变回 **Live**（约 1–2 分钟）。
3. **自动验证**（在你的电脑上，仓库目录里）：
   - Windows PowerShell：
     ```
     $env:ADMIN_PASSWORD="你的管理员口令"
     npm run verify:codes -- https://anchor.matchgamers.com
     ```
   - macOS/Linux：`ADMIN_PASSWORD=你的口令 npm run verify:codes -- https://anchor.matchgamers.com`
   - 期望看到 10 行"通过"和"全部通过"。脚本会临时创建几个验证用户和验证码，结束时删除用户并作废验证码，不留业务数据。
   - 有"失败"：**先不要对外发码**，把输出发给我；需要的话按下方「回退」。
4. **手动走一遍**（用手机或无痕窗口，3 分钟）：
   - [ ] 首次测试表单里出现「兑换码」一栏
   - [ ] 不填码提交被拦下；填错码提示"兑换码无效或已被使用"
   - [ ] 填长期通用码能开始答题，答完看到报告，能保存图片
   - [ ] 关掉页面后用邮箱 + 密钥回来，**不需要**再填码就能看结果
   - [ ] 后台「兑换码管理」里该码显示"已使用 1 / 100 人"
5. **收尾**：在 issue #15 里勾选完成并关闭；在周一清单里加上"看一眼兑换码使用情况"。

## 回退（1 分钟）
Render → Environment → 删除 `REQUIRE_CODE`（或改成 `0`）→ Save。已发出的码和已有数据都不受影响，表单里的兑换码栏会消失（如果还有开放的团队，会保留为"团队码（可不填）"）。

## 启用后的第一周
- 每天看一次「兑换码管理」：长期码的"已用 / 上限"。异常快增 → 作废，换一个新码，并告诉用户。
- 用户说"码无效"：先在后台查该码的状态（已用完、已过期、已作废？），再按 `07-support-and-feedback.md` 回复。
- 已知限制：用户注册后**输错码**时，账号会被创建但没有测试记录，这类用户在后台的记录列表里看不到（只在「清理旧数据」里按 12 个月清理）。如果这类用户多，告诉我，我把"用户列表"加到后台。

## 阶段 B：有真实订单时的切换步骤
1. 完成 #19（一次性码导出为闲鱼卡密），在闲鱼商品里配置自动发货。
2. 批量生成一次性码（备注写批次），导出并导入闲鱼。
3. **作废长期通用码**（后台 → 兑换码管理 → 作废）。已经开始答题的用户不受影响。
4. 手动买一单自己的商品，走完整流程（拍下 → 收到码 → 兑换 → 出报告）。
5. 团队客户：用「团队管理」创建团队，按团队版 SOP（#21）。

## 验证脚本检查了什么
`tools/verify-codes.js`（自动测试里也跑它，保证它本身是对的）：
1. 服务已启用兑换码 · 管理员口令有效
2. 不填码不能开始 · 无效码被拒
3. 有效的一次性码可用（忽略大小写）· 已有草稿时继续作答不需要码
4. 用过的一次性码不能再用
5. 通用码人数上限：第一人成功，之后"名额已满"
6. 已作废的码被拒 · 过期的码被拒
7. 清理：删除验证用户、作废验证码
