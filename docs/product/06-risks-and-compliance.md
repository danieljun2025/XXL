## 合规检查清单（每个涉及个人信息的需求都要过）
- [ ] 收集的每一项数据都有明确用途，能不收就不收
- [ ] 展示给第三方（团队负责人）的内容最少化，且**事先告知本人**
- [ ] 删除路径可用：联系 → 后台删除 → 确认
- [ ] 数据只存必要期限；到期清理的规则写进隐私说明
- [ ] 不向第三方发送个人数据；不引入第三方分析脚本（如需引入先写 ADR）
- [ ] 日志里不出现口令、密钥、完整邮箱
- [ ] 未成年人场景（学生）：不收集额外敏感信息，必要时提示需监护人同意

## 数据分类
| 数据 | 敏感度 | 保存方式 | 谁能看到 |
|---|---|---|---|
| 姓名、邮箱 | 中 | 明文（用于识别） | 管理员；团队负责人仅在开启「看姓名」时看到姓名 |
| 查看密钥 | 高 | 加盐哈希 | 无人可见明文 |
| 答题与结果 | 中 | 明文 JSON | 本人（凭邮箱+密钥）；管理员；负责人仅看汇总 |
| IP | 低 | 加盐哈希 | 管理员（不可还原） |
| 管理员口令 | 高 | 环境变量 | 仅你 |
| 团队报告码 | 中 | 哈希 | 仅创建时显示一次 |

## 数据泄露/误展示应急
1. 立刻止血：改管理员口令、重新生成团队报告码、必要时暂停服务。
2. 评估范围：哪些人的哪些数据、多久。
3. 如影响到用户：用闲鱼聊天通知并说明处理办法。
4. 写事故记录，补测试和流程。
