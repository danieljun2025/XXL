# 客户支持与反馈闭环

## 渠道与响应时间
| 渠道 | 用途 | 目标响应 |
|---|---|---|
| 闲鱼聊天 | 售前咨询、售后问题 | 白天 1 小时内；夜间次日上午 |
| 闲鱼评价 | 满意度、改进线索 | 每周看一次，差评 24 小时内回复 |

所有沟通留在闲鱼内完成，不留站外联系方式。

## 常见问题与标准回复
| 问题 | 处理 | 回复要点 |
|---|---|---|
| 打不开链接/页面很慢 | 看监控；让对方换网络或浏览器 | 道歉 + 请对方刷新/换浏览器；服务异常要补偿时间或重发码 |
| 兑换码无效 | 后台查码状态（未使用/已使用/已过期/已作废） | 已用过 → 请用邮箱+密钥回看；过期/作废 → 视情况补发 |
| 忘记查看密钥 | 后台找到用户 → 重置密钥 | 告知重置后再次进入时输入的新密钥即为新密钥 |
| 想删除数据 | 后台删除用户 | 30 天内完成并回复 |
| 报告看不懂/不同意结果 | 引导看"潜在盲区"和"发展建议"；推荐解读版 | 说明这是自我认知参考，不是定论 |
| 要退款 | 对照退款规则（见 #13） | 未使用的码可退；已使用不退；故障未解决可退 |
| 团队负责人看不到汇总 | 说明「至少 3 人完成才显示」 | 提醒成员尽快完成 |

## 反馈进入产品的流程
1. **记录**：每条有价值的反馈在 GitHub 开一个 Issue（`type:feedback` 或直接是功能/bug），附原话和来源。
2. **归类**：同类反馈合并到同一个 Issue，并在里面累计出现次数。
3. **评估**：出现 ≥ 3 次的反馈，进入 RICE 评分；影响数据/隐私的立刻升级。
4. **闭环**：做完后在 Issue 里写结果；如果是某位买家提的，在闲鱼上回复他。
5. **每月**：回看本月反馈 Top 5，决定是否进入 Next。

## 买家调研（上线后做）
- 每月联系 3–5 位买家，用 5 个问题了解：为什么买、之前怎么做、哪里不满意、愿意付多少、会推荐给谁。
- 结论记入 `01-strategy.md` 的「竞争与差异化」。
