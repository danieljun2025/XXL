# PRD：管理后台分类标签页与设置注册表（#37）

- 状态：已发布（v1.4.0）　级别：M　PR：见 CHANGELOG

## 问题
后台功能越来越多（记录、统计、兑换码、团队、备份、清理、答题设置），入口堆在一个页面的顶部，每新增一个设置都要重新想"放哪里"。

## 目标
每个功能有固定的"家"；新增一个设置只需要在服务端登记一条。

## 信息架构（6 个标签）
| 标签 | 页面 | 内容 |
|---|---|---|
| 概览 | `/admin.html`（也是登录入口） | 关键数字、待办提醒（备份、清理、兑换码状态）、快捷入口 |
| 记录 | `/records.html` | 答题记录列表、搜索、筛选、查看报告、重置密钥、删除、导出 CSV |
| 统计 | `/report.html` | 统计报表（可按团队筛选） |
| 兑换码 | `/codes.html` | 生成、列表、人数上限、有效期、作废、恢复、导出 |
| 团队 | `/teams.html` | 团队与团队码、报告码、开关 |
| 设置 | `/settings.html#分组` | 左侧分组：答题体验 `#quiz`、兑换码与访问 `#access`、数据与隐私 `#data`、系统信息 `#system` |

导航是所有后台页共用的一个组件（`admin-nav.js`），登录后才显示；页面用 `<body data-tab="…">` 标出当前标签。保留原有网址，直接打开仍显示「无权访问」（ADR-0008）。

## 设置归档规则
| 设置影响什么 | 放在 |
|---|---|
| 答题者看到的流程、文案、提示 | 设置 · 答题体验 |
| 谁能进入、怎样发放（全局默认值） | 设置 · 兑换码与访问 |
| 数据保存、删除、备份、隐私承诺 | 设置 · 数据与隐私 |
| 运行状态、环境变量（只读） | 设置 · 系统信息 |
| 针对某个码或某个团队的设置 | 跟着对象走：兑换码标签、团队标签 |

## 怎么新增一个设置（开发者）
在 `server/server.js` 的 `baseSettings` 里登记一条：
```js
{ key: 'xxx', group: 'quiz', type: 'select', label: '名称', help: '说明',
  options: [{ value: 'on', label: '开' }, { value: 'off', label: '关' }], default: 'on' }
```
- `type`：`select`（下拉，值必须在 options 里）、`readonly`（只读，提供 `value()` 函数）、`action`（带按钮的操作，需要在 `settings.js` 的 `ACTIONS` 里加处理）。
- 值存在 `meta` 表（键 `setting:<key>`），没设置过用 `default`；在代码里用 `getSetting('xxx')` 读取。
- 设置页自动按分组显示，支持保存、「恢复默认」（`null` 表示恢复默认）、未保存提示；校验由注册表统一做。
- 记得：在 `docs/product/05-process.md` 的配置清单里加一行；影响隐私的设置要写明下限（如团队汇总最少人数不低于 3）。
- 测试：参考 `test/settings.test.js` 里"新增一个设置只需要登记一条"（用 `extraSettings` 注入）。

## 本次迁入注册表的设置
- 每页题数（答题体验，默认 5）
- 团队汇总最少完成人数（数据与隐私，3/5/10，最低 3；原来在 `config.json`）
- 数据库备份、清理旧数据（数据与隐私，操作项）
- 兑换码状态、版本、数据库大小、上次备份、运行环境（只读）

## 概览的待办提醒
- 备份：从没备份过、或超过 7 天 → 待处理；服务端在每次成功下载备份时记录时间（`meta.last_backup_at`，不含个人数据）。
- 清理：有超过 12 个月无活动的用户 → 待处理。
- 兑换码：已启用但没有可用的码 → 待处理（新用户进不来）；未启用 → 提示。

## 不做
单页应用重构、权限分级、设置修改记录（以后可加）。
